# Guest mip range on the host, and mip-chain resolves inside the draw pass (2026-10-13)

Branch `agent-2/20261013-2046-mip-lod` (from `perf-staging` 0da2e5a). Switch `FABLE2_MIPLOD_PROOF` (default on, `=0`
kill switch; Dev Launcher → Fixes → Render targets → "Mip-chain resolves inside the draw pass"). Evidence:
`out/validation/mip-lod/` (`arm.sh`, `gpu_all.sh`, `ctr.py`, `parity.py`, `harness/`, one folder per run).

Follow-up to `docs/tile-resolve-20261013.md`. Its hazard fix (bug-patterns row 80) put about 27 mip-chain resolves per
frame back on compute: the pass that renders mip level N + 1 samples the texture whose level N + 1 the resolve writes.

## 1. How the guest mip range reaches the host (no gap found)

Xenos clamps a fetch's LOD to the fetch constant's `[mip_min_level, mip_max_level]`, after the fetch and instruction
LOD biases. The host does the same on both shader paths:

- **Lower bound:** the sampler's `lodMinClamp` is the effective `mip_min_level`
  (`BuildSamplerParametersFromFetch` → `texture_util::GetSubresourcesFromFetchConstant`, which also forces it to 1
  when the base address is 0).
- **Upper bound:** the sampler's `lodMaxClamp` is `FLT_MAX`, but the host texture has exactly `key.mip_max_level + 1`
  levels, and `key.mip_max_level` is the effective fetch `mip_max_level` (`BindingInfoFromFetchConstant`). The SRV
  view covers all levels of that texture, so the host LOD clamps at the guest's maximum.
- **Base-map filter:** `lodMaxClamp = mip_min_level` (+0.25 for point mip filtering, Xenia's rule), so only
  `mip_min_level` is read.
- **LOD itself:** the native translator and the DXBC path compute the same LOD. The fetch constant bias is the signed
  10-bit field / 32, plus the instruction bias. Computed-LOD fetches pass the derivatives scaled by `exp2(bias)`;
  register-LOD fetches pass `level()`. Both sample through the same sampler heap entry, so the clamps above apply.

So the premise "the host LOD is not clamped to the guest range" does not hold. The mip-chain hazard comes from the
guest itself. `FABLE2_MIPLOD_TRACE=1` (Bower 2× spin) on every in-pass hazard fallback found the following:

| What | Value |
|---|---|
| Textures | 14 per frame, 256×256 `k_1_5_5_5`, 4 levels (`mip_max_level` 3), packed mips |
| Written levels | 2 and 3 (64×64, 32×32), plus level 1 |
| Pass shaders | VS `D5E12A97B3A84881` (passthrough: `oPos = vfetch float3, w = 1`, `o0 = vfetch float2`), PS `06547412E4B72251` (`tfetch2D r0, r0.xy, tf13` → `oC0`), triangle list, 6 indices |
| Fetch constant | mip range **0–3**, min/mag/mip linear, LOD bias −1.0; the instruction uses the computed LOD |

The fetch constant allows every level, including the one being written. On the console, only the derivative LOD keeps
level N + 1 at weight 0: a quad of the level-(N + 1) size gives LOD N + 1, and −1 brings it to exactly N. No clamp
that copies the fetch constant can exclude N + 1. Proving the draws don't read it needs their LOD.

## 2. Per-draw LOD bound (`metal_miplod_proof.{h,cc}`, `metal_miplod_draw.cc`)

From guest state only, for draws that sample a **candidate** texture (one that a fused resolve has written as a whole
stored mip level, `kRttClassMipLevel`):

1. **Shader analysis** (once per shader, a `ShaderTranslator` subclass that tracks where each register component
   comes from; it fails on any conditional exec, loop, call or jump):
   - PS: every fetch of the fetch constant is a 2D `tfetch` with computed LOD, no register LOD or gradients,
     normalized coordinates, not predicated. Its coordinate x/y must be interpolant components unchanged since entry.
     `max r, a, a` with identical operands counts as a move; anything else makes the value unknown.
   - VS: the position X/Y must come from float32 vertex fetches indexed by the vertex index, with W the constant 1
     (so attributes are affine on screen). The same goes for the interpolant the PS reads (or a constant).
2. **Draw checks:** host VS type `kVertex`, not tessellated; triangle list/strip/fan or rectangle list; no primitive
   reset; at most 1024 vertices; auto-indexed or guest DMA indices; the interpolant is in the PS interpolator mask, not
   centroid, not parameter generation.
3. **Vertex data** is read from the shared-memory buffer (shared storage, so what the GPU reads) through
   `MetalSharedMemory::StableContents`: the range must be valid, and no GPU write, staged copy, pre-commit copy or
   standalone command buffer that is still in flight may touch its pages. Indices go through the shader's own
   transform: closing index, endian swap, offset, 24-bit mask, min/max clamp. Words go through the vertex fetch
   endian swap and `exp_adjust`.
4. **Gradient per triangle:** positions are scaled to host pixels by `ndc_scale × viewport extent / 2`, then solved
   for du/dx, du/dy, dv/dx, dv/dy. ρ = max over the two axes of the **L1** norm of the texel-space gradient (host
   texture size). L1 is not below the Euclidean or max norm a sampler may use. The bound is
   `log2(ρ) + fetch bias + instruction bias`, maximized over triangles and fetches.
5. **Levels read:** for every sampler of the fetch constant (anisotropic → unbounded),
   `max(mip_min, ceil(bound − 2^-12))`, or `mip_min` for base map. The result is clamped to the texture's levels.
6. **The draw samples a view of levels 0..bound** (`miplod_view_levels_`, `GetOrCreateView` level range; part of the
   SRV key, so descriptor reuse cannot keep a stale view). Whatever its own rounding, the host GPU cannot read a
   higher level.

**Hazard rule.** Every candidate-texture sampling since the last encoder end (an epoch per open pass) records the
highest level it can read, or "unbounded" (vertex-stage bindings, failed proofs). A fused resolve into stored mip
level W skips the two fused-target checks of row 80 only when every such sampling in the open pass is bounded below
W (`MipLodPassSafeForLevel == 2`). Otherwise the old checks run unchanged. The draws then read levels ≤ W − 1 through
views that end there, and the tile stage writes level W through a level view: disjoint subresources.

**Faithfulness.** Under the guest's exact arithmetic the bound is the LOD itself (Bower: exactly 0, 1 and 2 for the
level-1/2/3 passes). So the view excludes only what the console gives zero weight. The 2^-12 tolerance is below any
hardware's LOD fraction precision. The offline harness below shows Apple's GPU already gives level N + 1 zero weight
in these draws, so the view changes no pixel.

## 3. Exactness

**Offline harness** (`tools/shaderlab/miplod_view_diff.mm`, `out/validation/mip-lod/harness/`). It renders the
pass's shape: a quad over the level-(N + 1) target, UV 0..1, the native translator's gradient code with bias −1 and
the rounding offset, trilinear. Scales 1–3, written levels 1–3, 16 variants each (sub-pixel quad offsets, both
triangle orders). It compares full view + poison A, full view + poison B, and a view of levels 0..N:

| Run | values where level N + 1 had weight | limited view differs |
|---|---|---|
| bias −1 (the game) | **0** of 4.8M px × 4 | **0** |
| bias −0.999 (LOD N + 0.001) | 0 | 0 |
| negative control, bias −0.9 (LOD N + 0.1) | 19,267,584 | 19,267,584 |

**In game, tile verify** (`FABLE2_TILE_RESOLVE_VERIFY=1`, spin5, proof on; it compares each tile resolve with the
compute resolve byte for byte):

| Scene | 1× | 2× | 3× |
|---|---|---|---|
| Bower | 30,000 / 0 | 20,000 / 0 | 10,000 / 0 |
| Old Tomb | — | 6,000 / 0 | 2,000 / 0 |
| Bowerstone Old Town (`hero1-dog-live_2026-10-04_14-07-34`) | 12,000 / 0 | 8,000 / 0 | 4,000 / 0 |

92,000 resolves, **0 mismatches**, all verdicts ok. Mip-chain tile resolves per frame (`tr_n_tres_miplod`): Bower
28 (1×), 23–33 (2×), 13–34 (3×; verify ends each pass early); town 5–8; Old Tomb 0 (it has no mip-chain passes).
Hazard fallbacks (`tr_n_tres_fb_hazard`), Bower 2×: 33 → 4 per frame.

**Parity** (spin5, `parity.py`, on vs `FABLE2_MIPLOD_PROOF=0`): Bower 2× idle median 0.49% / max 2.07%, idle2
0.98% / 7.67%; town 2× idle 1.95% / 5.06%, idle2 6.09% / 48.4% (falling snow and where the camera stops). That is
within the earlier off-vs-off spread (2.86% / 14.0%). An area run at 2× with the proof on: verdict ok, 0 AV.

## 4. Performance (M5 Max, GPU ms/frame, `f2diag gpu` over the sweep window, pinned agent cache `e05b84cb5ec9220c@10`, no contention)

headings8-long unless noted, `FABLE2_MIPLOD_PROOF=0` → default (on):

| Scene / scale | off | on | Δ |
|---|---|---|---|
| Bower 1× (4 pairs) | 6.25, 6.02, 6.18, 6.09 | 6.29, 6.20, 6.09, 6.03 | +0.04, +0.18, −0.09, −0.07 (mean +0.02, flat) |
| Bower 2× (2 pairs) | 7.60, 7.63 | 7.54, 7.55 | **−0.06, −0.08** |
| Bower 3× | 11.89 | 11.90 | flat |
| Town 1× / 2× / 3× | 9.01 / 10.14 / 12.53 | 9.05 / 10.31 / 12.52 | flat (town is noisy: p50 2× 9.62 → 9.69) |
| Old Tomb 2× (headings8) | 5.35 | 5.37 | flat (no mip-chain passes) |

headings8 (short) showed the same: Bower 1× 6.24 → 6.40, 2× 7.88 → 7.73, 3× 12.14 → 12.18; town 1× 8.84 → 8.96,
3× 12.55 → 12.55. All are within the ±0.15 ms noise.

**Mechanism** (Bower, per frame): tile resolves 25 → 58, compute encoders 63 → 32, `direct_host_resolve` encoders
44 → 13. Per-key GPU spans (`keydiff.py`, 2×): `direct_host_resolve` −256 µs. The small mip-chain render passes grow
by +190 µs (320×256, 160×128: the tile dispatch now runs inside them), so the net is about −0.07 ms. At 1× the
same trade is about even. On the M5 Max this is a 30-encoder cut with close to no GPU time change. Encoder count
matters more on the M3 Pro, where per-encoder fixed cost is about 1.6× higher (census model,
`docs/hle-census-20261013.md` §8). With fixed ≈ 8 µs/encoder there, that projects to roughly −0.1 to −0.3 ms at 2×.
This is not measured; treat it as a direction.

**Default decision: on.** It is exact (verify 0 mismatches in 9 scene/scale runs, harness 0 differing values,
parity in noise). There is no regression beyond noise in any scene or scale, and a small consistent gain at Bower 2×
(the M3 Pro target).

CPU cost: the proof runs only for draws that sample a candidate texture (about 65 per frame in Bower). Shader
analysis is cached per shader. A proof reads 6 indices and 24 vertex words, so it is negligible next to the draw
setup.

| Switch | Default | Meaning |
|---|---|---|
| `FABLE2_MIPLOD_PROOF=0` | on | Kill switch: no bound, no limited views, mip-chain resolves stay on compute (as before). Dev Launcher toggle |

pass's conditional-exec shader `C915912C`).

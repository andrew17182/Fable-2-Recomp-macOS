## 1. The shadow mask: mostly the game's own shader work

### What the pass is (Bower 2×)

The pass binds `630t <14t> 1× D24S8` and `0t <14t> 1× 8888`, 1120×720 guest (2240×1440 host). It has two
full-screen quads.

- **Draw 1** (PS `1B4B5AE12EF270CA`, alpha test GREATER):
  - samples the main-depth resolve (`tf13`, 1120×720 scaled);
  - for far pixels, adds a 4-tap PCF on the far cascade;
  - writes colour and stencil 0xFF where the alpha test passes.
- **Draw 2** (PS `0F99810F072BF0FC`, stencil NOTEQUAL 0xFF): runs on the remaining near pixels, with 12 rotated-disk
  taps on the near cascade, 4 PCF taps on the far one and a noise fetch.
- Then a tile resolve copies the colour to a 1120×720 `k_8` texture, which the main pass samples.
- Around it, from `docs/main-depth-20261014.md`:
  - P8a's self-depth transfer pass moves main depth `[1008, 1260)` into `630t 1×`;
  - P8b's stencil-only clear runs as a separate small pass.

### Cost

| Item | 2× µs/frame | 3× µs/frame |
|---|---|---|
| Mask pass (2 draws + in-pass tile resolve, load/store) | 487–532 | 1151 |
| P8a self-depth transfer pass | 95–102 | 217 |
| P8b stencil-only clear pass | 36–43 | 108 |
| Total | ≈ 0.68 ms | ≈ 1.48 ms |

It scales with pixels (2.2× for 2.25× the pixels).

To split the pass, each draw was skipped by its vertex shader (`FABLE2_SKIP_VS`, diagnostic):
- draw 1 alone: 228 µs;
- draw 2 alone, full screen: 417 µs.

So draw 2 is ~300 µs of real per-pixel PCF work, and draw 1 plus the attachments and the resolve ~230 µs.

### What was tried

1. **Gradient-free sampling** (diagnostic `FABLE2_DIAG_LEVEL_PS`, since removed).
   - The native translator samples every computed-LOD fetch with `gradient2d(dfdx·2^bias, dfdy·2^bias)`. Sampling
     the two mask shaders at the fetch constant's LOD instead: 487 → 445 µs (−42).
   - For every pixel shader: −0.21 ms GPU at 2×, mostly main-pass shaders on mipmapped textures. That run is not
     exact: it is only an upper bound.
   - An exact version needs the texture to be single-level with min = mag filter and no aniso. That is known per
     draw only, which the variant mechanism below could carry. Not built: only post shaders qualify, about 0.05 ms.
2. **P8b's stencil clear folded into the tile-resolve pass** (kept open for it).
   - It works: the separate 36 µs pass is gone.
   - But the stencil quad drawn after the tile dispatch made the mask pass 100 µs slower: net +70 µs on the M5.
     Dropped. It would save 32 MB of load/store at 2×, but the in-pass quad costs more than that here.
3. **Whole-target in-pass deferred clears as clear load actions** (`FABLE2_CLEAR_LOAD_ACTION`, kept, default on).
   - The mask pass loaded its colour target and then drew P7's full-target clear (word `0xC0000000`) as a quad.
   - Now a deferred clear that covers its whole attachment, drawn at the start of a new draw pass, becomes the
     attachment's clear load action. It is applied to the descriptor right before the encoder is made and restored
     after.
   - The value conversion is the one the transfer pass already uses for its own whole-target clears, now shared as
     `ClearValueAsLoadAction`. Only formats whose clear value is exact both ways are taken: depth, 8888,
     10:10:10:2 unorm, 7e3 float. Stencil-only clears never are. Counter `tr_n_ssm_clear_la` (2 per frame).
   - Mask pass 487 → 465 µs.
4. **Specializing the post blur `4BE4344C27016E04` again**, now native. It was on the built-in skip list, and
   specializing it still gives no change (170 µs either way). Its cost is the bilinear sampling, not the decode.
5. **Not done:**
   - merging P8a's transfer into the mask pass: it needs the stencil-only clear after the transfer quads, the reverse
     of the in-pass order; about 50 µs at 2× on the M5;
   - a guest-resolution copy of the blur sources: the footprint's box filter read as point samples. Exact only into
     a 32-bit float texture.

## 2. The effects footprint: code that never applies still cost 0.5 ms

The pass trace, `FABLE2_EFFECTS_FOOTPRINT=0` vs default at Bower 2×, shows the footprint costing 0.68 ms of GPU time,
not only in the bloom passes. The main colour pass grew 1.94 → 2.30–2.38 ms. The texture-space chains and the shadow
mask grew too.

The native translator emits the footprint for **every** 2D fetch with a texel offset in a pixel shader. It checks at
run time whether that fetch's texture is resolution-scaled, of a colour format, and linear or point-on-clamp
(`fpon` / `fplin` / `fpcell`). In the main pass those fetches are:
- the 5×5 PCF of the shadow cascades (`tf6`: `k_24_8_FLOAT`, 1024², excluded by format);
- a 2×2 point PCF on a 1×1 `k_8_8_8_8` texture (`tf9`, never scaled).

The footprint never applies to them. The runtime tests, coordinate selects and the runtime-selected sampler still
slowed these long shaders. 30 such sites in `44B567635EB10620` / `3275A966F62EA3B1`, 3 in the common terrain shaders.
At 3× the old code already branched, so the main pass did not grow there.

Things that did not help:
- **Static samplers.** Each sampler in its own branch instead of a sampler variable: GPU 7.19 → 7.33.
- **One CPU-computed system-constant bit per fetch constant** instead of the per-fetch format and scaled tests:
  no change. Specialization does not bake a dword that its live-dword index never saw.
- **The coordinate math moved inside a uniform branch:** main pass 2.29 → 2.06, but the active bloom passes got
  slower (0.49 → 0.56), because branches around every tap break the fetch batching.

### Fix: `FABLE2_EFFECTS_FOOTPRINT_VARIANT` (default on)

- **The variant bit.** A Metal-only pixel-shader modification bit (`MetalPipelineCache::kPixelModificationFootprint`,
  dword 1 bit 28, unused by the DXBC translator) selects the translation.
  - With the bit, the native MSL is today's footprint code, unchanged.
  - Without it, the shader is translated with `effects_footprint` off: exactly the code before the footprint existed.
- **When the bit is set.** `MetalCommandProcessor::FootprintVariantNeeded` sets it per draw when at least one 2D
  fetch with a texel offset along a 2×/3× axis has a texture that is:
  - of a format other than `k_24_8`, `k_24_8_FLOAT`, `k_16`, `k_16_FLOAT` or `k_32_FLOAT` (the translator's own
    rule);
  - resolution-scaled now.
  The fetches come from `MetalShader::OffsetFetchConstantMasks`, computed once from the analyzed ucode.
- **Why the variant without the footprint is the same shader for that draw.** When no fetch qualifies, every
  footprint site of the old shader evaluates `fpon` false. With `fpon` false it samples with the fetch's own sampler
  at the original coordinate, which is the code without the footprint.
- **Knowing "scaled" before the textures are requested.** The modification is computed before `RequestTextures`. A
  small SDK patch (`backends/metal/sdk-metal-ssmask.patch`) adds `TextureCache::IsFetchConstantScaledResolve`: the
  memoized binding key → `GetHostTextureKey(...).scaled_resolve`, the same host key the request computes. Scaled
  ranges change only with resolves, never inside one draw.
- **Verify counter.** `UpdateSystemConstantValues` checks each draw against the textures' actual scaling:
  `tr_n_fp_variant_miss` (stays 0).
- **Diagnostic.** `FABLE2_EFFECTS_FOOTPRINT_TRACE=1` logs each (shader, fetch constant, format, size) that selects
  the footprint variant.
  - At Bower 2× these are the half/quarter-res bloom and blur shaders (`4BE4344C`, `28DBE18F`, `EA83C7E7`,
    `87E85199`, `0A96B3FD`, `5821366E`, `EE922CFB`);
  - the composite (`37B186F4`, `577CB526`, `686DE15F`, `93E7F7B5`);
  - two texture-space chain shaders (`5F329DB1`, `1B52AA35`).
- **Cost.** Translations: a shader with an active footprint gets one more variant, but only for those draws. Shaders
  in the specialization list that take the footprint variant (the composite's `0542FFDF` / `577CB526` / `686DE15F`)
  start without learn data for the new modification and specialize again once learned.
